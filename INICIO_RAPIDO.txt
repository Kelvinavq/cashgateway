  Guia de inicio rapido

ESTRUCTURA
----------
cashgateway/
  alters.sql          <- Schema MySQL + seed (admin + demo)
  README.md
  server/             <- Backend Express (Node.js)
    app.js / server.js
    config/           database, redis, env
    controllers/      auth, webhook, movements, accounts, domains, dashboard, deliveries
    routes/           7 archivos de rutas
    services/         accountResolver, movement, webhookForward, socket, stats
    queues/           webhookQueue + webhookWorker (BullMQ)
    middlewares/      auth (JWT cookie), error, rawBody
    utils/            hmac, logger (Winston), validators
  client/             <- Frontend React + Vite + MUI
    src/
      pages/          Login, Dashboard, Movements, Deliveries, Accounts, Domains
      components/     Layout (sidebar), StatusChip (badges)
      contexts/       Auth, Theme (claro/oscuro persistente)
      lib/            api (axios), socket (Socket.IO)


PARA EMPEZAR
------------

1. BASE DE DATOS
   Importar en MySQL (crea DB, tablas, indices y datos de ejemplo):

   mysql -u root -p < alters.sql

   Esto crea:
   - Usuario admin: admin@hgcash.com / admin123
   - Dominio de ejemplo: "Demo Project"
   - Cuenta HG de ejemplo: AGROFORESTAL PAMPA

2. BACKEND (abrir DOS terminales en /server)

   Terminal 1 - Servidor principal:
   cd server
   npm install
   npm run dev

   Terminal 2 - Worker de colas BullMQ:
   cd server
   npm run worker

3. FRONTEND

   cd client
   npm run dev

   Abrir en el navegador: http://localhost:5173

BUGS CORREGIDOS DURANTE EL DESARROLLO
--------------------------------------
1. movementsController: el filtro delivery_status se construia fuera del WHERE.
   Corregido con EXISTS subquery — ahora el filtro se aplica correctamente.

2. app.js: express.json() global consumia el stream del body antes que
   el rawBodyMiddleware de la ruta webhook.
   Corregido: se agrego la opcion verify al parser global para capturar
   el raw body en todas las rutas sin conflicto.

3. movementsController: GROUP BY m.id con SELECT * podia fallar en
   MySQL con ONLY_FULL_GROUP_BY activado (modo strict por defecto).
   Corregido: se elimino el GROUP BY y se reemplazaron las columnas
   implicitas por una lista explicita de campos.

EVENTOS SOCKET.IO (tiempo real)
--------------------------------
  movement:new       <- nuevo movimiento recibido
  movement:updated   <- movimiento actualizado
  delivery:updated   <- estado de entrega cambiado
  stats:updated      <- estadisticas del dashboard actualizadas


REINTENTOS AUTOMATICOS (BullMQ)
--------------------------------
  Intento 1: inmediato
  Intento 2: 5 segundos
  Intento 3: 10 segundos
  Intento 4: 20 segundos
  Intento 5: 40 segundos
  Backoff exponencial. Maximo 5 intentos.
  Luego se marca como "failed" y se puede reintentar manualmente.
